### Meet Altrone 4.0 - our biggest release ever

Altrone 4.0 gives you more ways to build applications, from responsive layouts with side panels to complex tables and ready-made dialogs. We've added new components, expanded familiar ones, and given you more freedom over how they look and work within your application.

1. **A new design across the library.** We've rethought how components look and fit together. Materials, shapes, typography, and animations form a shared visual language for building entire applications.

2. **More freedom to make it your own.** CSS variables let you tailor the interface to your product, while local overrides let you set a theme, accent, and other options for a specific area. Different parts of the same application can have their own appearance.

3. **Your icons throughout the interface.** You can replace the built-in icon set in one place, so even the internal elements of components use icons that belong in your product. The setting applies across the entire library.

4. **Eight languages for your applications.** Simplified Chinese, Portuguese, and Turkish join the supported languages. A shared language setting keeps built-in labels consistent, while local overrides let you change the language and text for a specific part of the interface.

5. **More ways to work with the keyboard.** Navigate nested menus, choose colors, switch sections, and sort tables without a mouse. Components expose their state to assistive technologies, helping you build interfaces for a wider audience.

6. **Your application controls the interface state.** More components support external state management: open panels, workspace dimensions, selected files, and table settings can all connect to shared state. This lets you save layouts, keep filters in sync with the URL, and coordinate actions across the screen.

7. **Flexible composition with your own elements.** A consistent `asChild` approach lets you use your own element as the foundation of a component. It helps you adapt the markup to your application and combine Altrone's capabilities with an existing interface.

8. **Five sizes for controls.** From compact toolbars packed with actions to spacious forms, you can choose the right scale for your interface. A shared scale of five sizes helps buttons, fields, and other controls work together with consistent proportions.

Below are the new features by component, collected from the [release notes on GitHub](https://github.com/apcom52/altrone-ui/releases).

**Application.** Making Altrone your own is easier: you can replace the built-in icons across the entire library, while the new Override component lets you set a separate theme, accent, language, labels, and icons for any part of the interface. Application also manages the browser tab title, combining the application name with the active screen's name. You can override the title from anywhere, even outside React. Theme settings also expose the user's preference, including automatic mode.

**Screen.** This new component helps you build the foundation of an application: a header, collapsible sidebar, additional column, footer, and navigation. Bring them together in a responsive layout for different devices. You can control side panels from your code, the header's toggle button connects to the sidebar automatically, and the header itself can stay fixed or remain in the page flow.

**Box.** A new building block for your interface: choose a material, shape, spacing, and interaction, then use it as the foundation for your own elements. The materials include frosted glass, a dotted pattern, and an opaque tinted surface called pale.

**Text.** More freedom with typography: an expanded size scale, truncation for long text, and new options for links. A single component's props define how the text is presented.

**Image.** Images now have a component of their own. Use it to place a picture in your interface and add a caption when needed.

**Grid.** Row and column gaps can now be configured separately, letting you tailor the grid to your page's content.

**Flex.** A shared spacing scale helps you maintain a consistent rhythm between elements throughout the interface.

**Drawer.** This new sliding panel is useful for viewing records, creating entries, and editing large forms. It opens from the left or right and includes everything you need for a header and action buttons. You control its state and decide how users can close it: for example, you can hide the close button and prevent dismissal through the backdrop or Escape. In that mode, an attempted dismissal produces a gentle shake, while scrolling on the page behind the panel is locked.

**Popover.** A popup can now appear over the element that opens it. You can connect its state to your application or open and close it programmatically through a separate `controlRef`.

**Dropdown.** Long menus can limit their own height and scroll their content. Nested menus support keyboard navigation: open a submenu with the right arrow or Enter, and go back with the left arrow or Escape. Handlers receive the original events, making it easier to connect menu actions to your application's logic.

**Tooltip.** Tooltips can include a title and a keyboard shortcut, helping you explain an action and show a faster way to perform it.

**Modal.** A modal can now be opened from anywhere, without wrapping a trigger button. Animations and keyboard accessibility have also been improved.

**Scrollable.** Scrollable areas now share the OverlayScrollbars engine. It also powers scrolling inside modals, drawers, split panels, and long menus, giving the library a consistent scrollbar appearance. You can access the scrolling element directly for custom behavior.

**Form.** You can now set the size and disabled state for an entire form at once. All Altrone controls inherit these settings, from text fields and switches to date, color, and file pickers.

**Splitter.** This new component lets you build a workspace with several panels that users can resize themselves. Arrange panels side by side or vertically, allow them to collapse, and set size limits. If your application needs to control the layout, you can keep panel sizes in external state. Each panel can be styled directly, without an extra wrapper.

**Spoiler.** Content now animates as it expands and collapses. You can track and change its state from your application, for example by connecting a section's expansion to other user actions.

**Toolbar.** Toolbar has grown from a simple tool strip into a foundation for headers and groups of actions throughout your application. Add a title, group buttons, and choose their alignment, size, and screen edge. Actions have all the capabilities of regular buttons, and move into an overflow menu when space runs out. A new priority system lets you decide which actions remain visible as the screen gets narrower.

**Button.** Buttons can communicate the outcome of an action: success and error animations join the loading state. A built-in tooltip helps explain the action, while display variants reflect its purpose, from a text button to form submission.

**TextInput.** Dynamic islands are more useful: they can contain full-featured action buttons and a character counter. You can also style the input itself separately from its outer container.

**PasswordInput.** Password fields gain TextInput's new capabilities: action buttons and a character counter in dynamic islands, along with separate styling for the input.

**NumberInput.** Numeric fields also gain the new islands with action buttons and a character counter. You can style the input independently of its outer container. The built-in stepper on the right side of the field has been removed.

**AutocompleteInput.** More options for building the suggestions list let you tailor it to your application's data.

**Search.** Search brings together the new text field and autocomplete capabilities: actions in dynamic islands, a more flexible suggestions list, and separate input styling.

**TextArea.** Dynamic islands are now available in multiline fields too. You can embed additional elements directly in the field and style the input separately from its outer container.

**Select.** There are more ways to tailor the selection control to your interface. Handlers receive the event object, while size and disabled state can be set along with the rest of the form.

**Checkbox.** Checkboxes gain size options and form integration: size, name, and disabled state can all come from the form context.

**Switch.** Choose a switch size to suit your interface, or set it for the whole form. Name and disabled state also come from the form context.

**Radio.** Radio groups support different sizes and shared form settings. You can leave the group unselected by default, letting users make the choice themselves.

**ColorPicker.** Choosing a color becomes a self-contained interaction with a title and explicit clear and apply actions. The color selection panel is fully keyboard-accessible. Size and disabled state can be set through the form.

**DatePicker.** A new handler is available for range selection, while shared form settings let you set size and disabled state alongside other fields.

**FilePicker.** Your application can now control the list of selected files. Connect uploads to your own state, set the placeholder text, and disable file selection either individually or together with the entire form.

**Slider.** A classic slider variant is now available for selecting a value. Its size and disabled state can be set through shared form settings.

**Calendar.** Calendar supports three scenarios: selecting a single day, multiple dates, or an entire range. It includes a header, navigation, date highlighting, and date display options. The locale is inherited automatically from the application.

**DataTable.** Tables gain the TanStack Table engine and more ways to work with data. Column types determine cell rendering and available filtering; data loading and column resizing are supported. You can connect the current page, sorting, and filters to the URL or your application's store, and assign custom identifiers to rows. The header can contain a full Toolbar with several action areas, while wide tables have their own horizontal scrolling with a synchronized header. Columns can be excluded entirely from the table, sorting, and filters, for example based on user permissions.

**Dialogs.** Common interactions no longer require building a modal from scratch. The new `showAlert`, `showConfirm`, and `showPrompt` functions let you display a message, request confirmation, or ask for a value.

**Progress.** You can now set a lower bound for the progress indicator to match the range of values you need.

**Tags.** Give each tag its own custom control and choose a component size that fits the surrounding interface.

**Notifications.** The new notification engine lets you add an image, choose how long a notification appears, and define when it closes. Toasts and notifications can be triggered with plain functions from anywhere in the application, even from a store outside React components. A shared setting determines which corner of the screen they appear in.

**Result.** This new component helps explain the state of an entire area of the interface: an operation succeeded, an error occurred, access is restricted, or there is nothing to show yet. It places the message in the center of a block and works for a wide range of application states.

**NavigationList.** Navigation gains fixed headers and footers. Items can be tailored to your interface, and regular action buttons can be added to groups and links.

**BottomNavigation.** Bottom navigation can be fixed to the screen, with a dynamic backdrop highlighting the active section. You can override its controls, and links are keyboard-accessible.

**Tabs.** Locked tabs and support for different sizes have been added.

**Pagination.** The new pagination uses a familiar row of page numbers, with options for how many numbers and navigation buttons to show. Choose a size and let the component manage the current page itself by providing only an initial page.

**Avatar.** Avatars offer more flexibility: background and text colors can be set independently, and an icon can replace initials. An icon avatar does not require a first or last name.

**Label.** A new component for short labels and statuses. Choose a shape and color, add an icon, or use one of the available variants.

**Loading.** The indicator can show a specific completion percentage as an arc. Set its size with a number or any CSS unit, and choose a color to suit its surroundings.

**Skeleton.** This new component helps show the page's upcoming structure while data is loading. Build an animated placeholder layout with configurable dimensions, size limits, and corner rounding.

**CloseButton.** The close icon can now be replaced with your own to match the rest of your application's icons.
