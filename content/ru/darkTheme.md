# Тёмная тема

Тёмная тема в Altrone — это не отдельная таблица стилей, которая подключается вместо основной. Это те же компоненты, тот же CSS, читающий те же токены — просто сами токены переопределяют, во что они резолвятся, под атрибутом темы. Если компонент построен правильно (использует ролевые токены из статьи [Цвет](color) вместо вписанных значений), тёмная тема достаётся ему бесплатно, а не требует отдельной реализации.

## Как на самом деле работает переключение темы

Altrone отслеживает тему как явное состояние, а не полагается исключительно на медиа-запрос `prefers-color-scheme` уровня ОС. Это соответствует соглашению, которое используют такие библиотеки, как next-themes и Radix Themes: текущая тема — `'light'`, `'dark'` или `'auto'`, хранится в состоянии React и выражается через `data-altrone-theme` — атрибут, а не класс — установленный на корне приложения.

```tsx
import { useAltroneTheme } from "altrone-ui";

function ThemeSwitcher() {
  const { theme, setTheme } = useAltroneTheme();

  return (
    <button onClick={() => setTheme(theme === "dark" ? "light" : "dark")}>
      Текущая: {theme}
    </button>
  );
}
```

::playground{src=ThemeToggleDemo caption="Переключите тему и посмотрите, как карточка ниже следует за ней — без какого-либо кода на уровне компонента"}

`'auto'` резолвится относительно `window.matchMedia('(prefers-color-scheme: dark)')` — так что тот, кто ни разу не вызвал `setTheme`, всё равно получает тему, которая следует за ОС, просто не привязан к ней намертво, если позже захочет явный переключатель.

Каждый цветовой, теневой и граничный токен в библиотеке определён дважды: один раз на верхнем уровне, ещё раз — в области видимости `[data-altrone-theme='dark']`. В CSS самого компонента между темами не меняется ничего — меняется только то, во что резолвится каждый токен в данный момент.

```scss
/* Упрощённая форма того, как на самом деле выглядит файл с токенами */
:root {
  --background-1: white;
}

[data-altrone-theme="dark"] {
  --background-1: #0d0d0f;
}
```

## Где живёт атрибут

`data-altrone-theme` устанавливается в двух местах по двум разным причинам:

- На **корне компонента** (элемент с `data-altrone-root="true"`, который рендерит `<Application>`) — именно к этому элементу привязаны все переопределения тёмной темы в CSS самих компонентов Altrone.
- На **`<html>`** — для стилей, которые применяются полностью за пределами `data-altrone-root`: глобальных правил, не привязанных к конкретному компоненту, вроде `::selection`, и всего, что рендерится через портал и оказывается вне корневого элемента.

Обычно вам не нужно читать или устанавливать этот атрибут напрямую — `useAltroneTheme()` — поддерживаемый способ прочитать текущую тему и изменить её.

:::note
Раньше вместо атрибута использовался класс `.AltroneDark`. Он полностью убран — если вы встретите его где-то (в форке, в старом сниппете), это мёртвый код с тех времён до того, как утвердилось текущее соглашение.
:::

## Как избежать вспышки неправильной темы

Поскольку состояние React не существует до гидратации, страница с тёмными системными настройками иначе на мгновение отрендерилась бы светлой, а затем переключилась на тёмную — вспышка неверной темы (FOUC). `Application` рендерит небольшой блокирующий скрипт самым первым в своём выводе — он устанавливает `data-altrone-theme` на `<html>` до того, как остальное дерево успеет отрисоваться:

```tsx
import { getThemeInitScript } from "altrone-ui";

// примерно то, что <Application> делает внутри себя:
<script
  dangerouslySetInnerHTML={{ __html: getThemeInitScript(initialTheme) }}
/>;
```

Это решение по принципу «лучшее из возможного» — разумное для библиотеки компонентов, не привязанной к одному конкретному SSR-фреймворку. Если вам нужна жёсткая гарантия при потоковом SSR (скрипт обязан выполниться до того, как хоть один байт вашей тёмной страницы дойдёт до отрисовки), рендерите `getThemeInitScript()` напрямую в своём собственном `<head>` документа, а не полагайтесь на копию внутри `Application`:

```tsx
// app/layout.tsx (например, Next.js App Router)
import { getThemeInitScript } from "altrone-ui";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <head>
        <script
          dangerouslySetInnerHTML={{ __html: getThemeInitScript("auto") }}
        />
      </head>
      <body>{children}</body>
    </html>
  );
}
```

## Сохранение выбора пользователя

Передайте `persistTheme`, чтобы запомнить явное переключение темы в `localStorage` и восстановить его при следующем визите:

```tsx
<Application persistTheme>{children}</Application>
```

:::note
Сохранение включается только **после** того, как пользователь хотя бы раз явно переключил тему. До этого момента решение принимает `theme`/системные настройки — так что `persistTheme` никогда не перекрывает явный проп `theme`, заданный потребителем, на пустом месте при первой загрузке.
:::

## Использование этих токенов в собственных компонентах

Несколько токенов существуют специально для того, чтобы поверхность корректно читалась в обеих темах — обращайтесь к ним вместо того, чтобы изобретать своё:

- **`--glass-background-color`** / **`--glass-border-color`** — заливка и край для любой полупрозрачной/матовой поверхности (модалка, drawer, дропдаун, карточка, которая должна выглядеть «приподнятой» над размытым фоном).
- **`--color-overlay-scrim`** — затемняющий слой за подложкой модалки или drawer'а.
- **`--tooltip-background-color`** — заливка тултипа. Тултипы намеренно не имеют ни рамки, ни тени (стрелка — отдельный SVG, который рамка не может корректно обогнуть), поэтому в тёмной теме за всю поверхность отвечает именно этот токен.

Имея их под рукой, для собственных компонентов действуют те же правила, что и внутри самой библиотеки:

1. **Никогда не пишите переопределение под тёмную тему для конкретного компонента, если сам токен не ошибочен.** Если вы ловите себя на написании `[data-altrone-theme='dark'] .myComponent { color: ... }` — остановитесь: почти всегда это значит, что был пропущен ролевой токен, а не то, что этот компонент — настоящее исключение.
2. **Проверяйте обе темы, прежде чем считать задачу выполненной.** Цвет, который «вроде работает» в светлой теме, может быть невидимым или еле заметным в тёмной — система токенов защищает от большинства таких случаев, но сырое цветовое значение, добавленное вами самостоятельно, такой защиты не получит.
3. **Если значению действительно нужен другой вид в тёмной теме** (редкий случай — почти ничему в библиотеке это не потребовалось), делайте переопределение через `[data-altrone-theme='dark']` для собственного токена — так же, как это делают `_glass.scss`/`_shadow.scss` самой библиотеки — не обращайтесь к `prefers-color-scheme` напрямую внутри CSS компонента, поскольку это игнорирует явный проп `theme`, который мог задать потребитель.

:::warning
Вписанное вручную hex-значение — самый быстрый способ сделать компонент невидимым в одной из двух тем. См. статью [Цвет](color) о том, зачем нужны ролевые токены и как выбрать подходящий.
:::
