# Spoiler

Сворачиваемая секция с анимацией высоты. Заголовок — нативная кнопка (`aria-expanded`, `aria-controls`), фокусируется и переключается с клавиатуры (`Enter` / `Space`). По умолчанию неуправляемый (состояние живёт внутри, стартует от `defaultOpen`), либо передайте `open`, чтобы управлять им снаружи — `onToggle` в обоих случаях сообщает о каждом клике.

## Базовый пример

```tsx
<Spoiler title="Что такое Altrone UI?">
  <p>Altrone UI — библиотека React-компонентов с современной дизайн-системой.</p>
</Spoiler>
```

## Раскрыт по умолчанию

`defaultOpen` задаёт начальное состояние неуправляемого спойлера. После первого рендера компонент живёт самостоятельно — проп игнорируется при повторных рендерах (для управления снаружи см. `open` ниже).

```tsx
<Spoiler title="Системные требования" defaultOpen>
  <Text block>React 18+, TypeScript 4.9+</Text>
</Spoiler>
```

## Список FAQ

Несколько `Spoiler` подряд образуют аккордеон без дополнительной обёртки. Они не связаны друг с другом — можно раскрыть сколько угодно одновременно.

```tsx
{faqs.map((faq) => (
  <Spoiler key={faq.id} title={faq.question}>
    <Text block>{faq.answer}</Text>
  </Spoiler>
))}
```

## Реакция на переключение

`onToggle` получает новое состояние (`true` — открыт) после каждого клика. Используйте для аналитики, ленивой загрузки содержимого или синхронизации с URL.

```tsx
<Spoiler
  title="Дополнительные настройки"
  onToggle={(open) => {
    if (open) loadAdvancedSettings();
  }}
>
  <AdvancedSettingsForm />
</Spoiler>
```

## Управляемое состояние

Передайте `open` (вместо `defaultOpen`), чтобы владеть состоянием снаружи — компонент отрисует то, что ему передали, и будет только просить об изменении через `onToggle`.

```tsx
const [open, setOpen] = useState(false);

<Spoiler title="Дополнительные настройки" open={open} onToggle={setOpen}>
  <AdvancedSettingsForm />
</Spoiler>
```

## Внутри формы

`Spoiler` хорошо работает как контейнер для опциональных полей формы. Пользователь видит основные поля сразу, а дополнительные раскрывает по мере необходимости.

```tsx
<Spoiler title="Дополнительные поля">
  <Form.Field name="notes" label="Примечания">
    <TextArea value={notes} onChange={(e) => setNotes(e.target.value)} />
  </Form.Field>
  <Form.Field name="tags" label="Теги">
    <TextInput value={tags} onChange={setTags} />
  </Form.Field>
</Spoiler>
```

## Свойства

:::prop[title*]{type="ReactNode"}
Всегда видимый заголовок (кнопка). Может быть строкой или произвольным узлом.
:::

:::prop[children]{type="ReactNode"}
Содержимое, скрытое в свёрнутом состоянии.
:::

:::prop[open]{type="boolean"}
Управляемое состояние открытия. Без этого пропа `Spoiler` неуправляемый — см. `defaultOpen`.
:::

:::prop[defaultOpen]{type="boolean" default="false"}
Начальное состояние для неуправляемого спойлера. Игнорируется, если передан `open`.
:::

:::prop[onToggle]{type="(open: boolean, event: MouseEvent<HTMLButtonElement>) => void"}
Вызывается после каждого переключения. `open` — новое состояние.
:::

## Рекомендации

**По умолчанию `Spoiler` неуправляемый.** Для большинства случаев (FAQ, второстепенные настройки) `defaultOpen` — это всё, что нужно. Переходите на `open`/`onToggle`, только если состояние действительно должно жить снаружи — например, синхронизация с URL или persist в localStorage.

**Не прячьте важное.** `Spoiler` подходит для дополнительного контекста, FAQ, вторичных настроек. Если содержимое критично для выполнения задачи — оно должно быть видно сразу.

**Анимация работает через `motion/react`.** Раскрытие — пружина по высоте с лёгким фейдом, закрытие — быстрый твин; `padding` вынесен на внутреннюю обёртку, чтобы не дёргаться вместе с высотой. Уважает `prefers-reduced-motion`. Не применяйте собственные переходы к содержимому — они будут конфликтовать с внутренней анимацией.

**Для одного активного блока реализуйте аккордеон явно.** `Spoiler` сам по себе не ограничивает одновременно открытые секции. Если нужно, чтобы раскрытие одного закрывало другие — управляйте состоянием снаружи через `onToggle`.
