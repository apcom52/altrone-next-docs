# Обратная связь

Altrone делит «сообщить пользователю, что что-то произошло» на несколько компонентов по двум реальным осям: **временное vs постоянное** и **императивное vs обычный JSX**. То, в какой квадрант попадает конкретная обратная связь, определяет, к какому компоненту обращаться — эта статья про то, как принять это решение, а не про полный API какого-то одного компонента.

## Временное, императивное: тосты и уведомления

`useNotifications()` даёт две функции, не требующие ничего рендерить самостоятельно — вызовите их, а стек (монтируется один раз через `<Application>`) сделает всё остальное:

```tsx
const { toast, notification, dismiss } = useNotifications();

// Короткое сообщение-таблетка — по умолчанию исчезает через 4с
const id = toast("Изменения сохранены", { variant: "success" });

// Более насыщенная карточка — заголовок, опциональная картинка, кнопки действий — исчезает через 6с
notification({
  title: "Экспорт готов",
  content: "Файл завершил обработку.",
  actions: [{ label: "Скачать", onClick: handleDownload }],
});

dismiss(id); // закрыть раньше, если нужно
```

Обе функции принимают `variant`/степень серьёзности `'default' | 'success' | 'warning' | 'danger'`. Ни одна не блокирует пользователя или остальной интерфейс — в этом и суть этого квадранта.

## Временное, императивное и блокирующее: диалоги

`showAlert`, `showConfirm` и `showPrompt` — обычные функции, а не компоненты: не нужно рендерить JSX диалога или управлять состоянием. Каждая возвращает `Promise`, который вы дожидаетесь через `await`:

```tsx
const confirmed = await showConfirm({
  title: "Удалить аккаунт",
  message: "Это действие нельзя отменить.",
  confirmText: "Удалить аккаунт",
  danger: true,
});

if (confirmed) {
  await deleteAccount();
  await showAlert({ title: "Готово", message: "Ваш аккаунт удалён." });
}
```

`showConfirm` резолвится в `boolean`, `showPrompt` — во введённые `string | number`, либо `null` при отмене — поток «подтвердить, затем сделать» это одна цепочка `await`, а не дерево колбэков. `danger: true` у `showConfirm` — тот же сигнал «это необратимо», что несёт проп `danger` у `Button` в других местах.

## Постоянное, обычный JSX: `Message` и `Result`

`Message` — это встроенный баннер, живущий в вашей собственной вёрстке — не стек, не исчезает сам. Его `severity` (`'default' | 'primary' | 'success' | 'warning' | 'danger'`) сама выбирает роль для объявления скринридером: `danger` получает `role="alert"` (assertive — прерывает, чтобы объявить), всё остальное — `role="status"` (polite):

```tsx
<Message severity="danger" header="Загрузка не удалась">
  Файл превышает лимит в 10МБ.
</Message>
```

`Result` — полностраничный/посекционный аналог: состояние исхода (`'empty' | 'info' | 'success' | 'warning' | 'error'`) с заголовком, описанием и рядом действий — для состояний «здесь пока ничего нет» или «вот чем закончилась операция», а не для проходного сообщения.

## Продолжающееся, а не исход: `Progress`

`Progress` сообщает, что что-то всё ещё происходит, и насколько далеко это зашло — `min`/`max`/`value`, с подписью по умолчанию `"{percentage}%"`. Он не временный и не состояние исхода — это то, за чем обычно следует `Result` или тост, когда операция реально завершается.

## Как выбрать нужный

| | Временное | Постоянное |
| --- | --- | --- |
| **Неблокирующее** | `toast` / `notification` | `Message`, `Progress` |
| **Блокирующее** | `showAlert` / `showConfirm` / `showPrompt` | `Result` (полностраничное состояние, из которого пользователь должен действовать) |

## Построение собственных компонентов

1. **Сначала решите временное/постоянное и блокирующее/неблокирующее.** Само по себе это решение обычно указывает на существующий компонент — редко это повод создавать новый.
2. **Обращайтесь к `showConfirm`/`showPrompt` вместо самодельной модалки**, когда нужен ответ да/нет или короткий текст перед продолжением — вы бесплатно получаете поток на основе `Promise`.
3. **Сопровождайте серьёзность иконкой или текстом, никогда не только цветом** — см. [Доступность](accessibility), почему.
4. **Сопоставляйте срочность объявления с серьёзностью**, так же как `Message` выбирает `alert` (assertive) только для `danger` и `status` (polite) для всего остального — полное руководство по `aria-live`, которое это отражает, см. в [Доступности](accessibility).
