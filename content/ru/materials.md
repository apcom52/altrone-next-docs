# Материалы

Почти любая стилизованная поверхность в Altrone — кнопки, карточки, чипы, плейсхолдер-заглушки — это `Box` внутри, настроенный, а не переоформленный заново. Материалы — это небольшой общий словарь, который это делает возможным: обработка заливки/блюра/границы (`material`), цветовая роль (`tone` или `color`) и одна модель взаимодействия (`pressable`/`focusable`/`editable`), которая ведёт себя одинаково независимо от того, какой материал или тон вы выбрали. Выучите этот словарь один раз — и сможете читать (или писать) оформление поверхности почти любого компонента в библиотеке.

```tsx
<Box material="solid" tone="accent" shape="pill" padding={{ x: 20, y: 10 }}>
  <Text weight="medium">Начать</Text>
</Box>
```

## Восемь материалов

Материалы отличаются только тем, что реально присутствует *в состоянии покоя* — модель взаимодействия поверх этого (ниже) одинакова для всех.

| Материал | В покое |
| --- | --- |
| `solid` | Полностью залит сплошным цветом тона, текст автоматически контрастирует относительно него |
| `glass` | Полупрозрачная заливка тона плюс блюр фона — матовое стекло |
| `plate` | Фиксированная матовая заливка, тонкая обводка и тень покоя, за счёт чего поверхность читается как приподнятая над страницей |
| `translucent` | Плоская полупрозрачная заливка тона, без блюра |
| `transparent` | Полностью прозрачный блок |
| `outline` | Статичная, всегда видимая граница |
| `ghost` | В покое ничего нет — граница появляется только при взаимодействии |
| `hatch` | Едва заметная тонированная заливка, тонкая обводка и диагональные штрихи — поверхность-заглушка для «здесь будет контент» и пустых зон для drag-and-drop |

`transparent` и `ghost` выглядят одинаково в состоянии покоя — разница проявляется только при наведении, нажатии или фокусе: `ghost` в этот момент рисует границу, `transparent` — никогда. Это реальное, осознанное различие, а не два имени для одного и того же:

```tsx
<Box material="ghost" pressable focusable>
  <Trash2 />
</Box>
```

## Tone: цветовая роль

`tone` (`neutral` / `accent` / `danger` / `success` / `warning` / `info`) выбирает, из какой роли [Цвета](color) берёт материал. Каждый материал маппит один и тот же тон одинаково — `solid` всегда обращается к сплошной ступени тона, граница `outline` всегда обращается к граничной ступени тона — так что смена `tone` корректно перекрашивает `Box` независимо от того, какой материал используется:

```tsx
<Box material="translucent" tone="danger">
  <Text>3 элемента требуют внимания</Text>
</Box>
```

## `color`: выход за пределы системы tone

`color` полностью переопределяет `tone` — передайте одно из десяти категориальных имён оттенков (`'teal'`, `'indigo'`, …) или любой CSS-цвет (`'#f0abfc'`, `'var(--my-token)'`), и каждый материал будет выводить свою заливку/границу/текст уже из него. Текст в `solid` всё так же автоматически контрастирует относительно переданного цвета — тот же приём, что использует `Avatar` для фона, привязанного к идентичности:

```tsx
<Box material="solid" color="teal" />
<Box material="translucent" color="#f0abfc" />
```

Обращайтесь к `tone`, когда цвет сообщает о *статусе* (опасность, успех, …), и к `color`, когда он сообщает об *идентичности* (категория, человек, кастомный брендовый цвет) — то же различие, которое [Цвет](color) проводит между статусными цветами и категориальной палитрой.

## Одна модель взаимодействия для всех материалов

- **`pressable`** — фон реагирует на `:active` (реально кликабельный `Box`, без состояния в JS). Наведение — более лёгкий предпросмотр того же изменения; нажатие доводит его на шаг дальше. Именно поэтому граница `ghost` «появляется при взаимодействии» — правило для границы привязано к тому же состоянию `:active`/`:focus-within`, которое уже отслеживают pressable и editable.
- **`focusable`** — добавляет кольцо `:focus-visible`, одинаковое по виду для любого материала, так что фокус с клавиатуры никогда не зависит от материала.
- **`editable`** — для `asChild` поверх нативного `input`/`textarea`: «включённый» вид срабатывает на `:focus-within` вместо `:active`, поскольку у текстового поля нет состояния нажатия, как у кнопки.

```tsx
<Box asChild material="outline" editable focusable>
  <input placeholder="Поиск…" />
</Box>
```

## Композиция с shape, size и elevation

`material`/`tone`/`color` отвечают за заливку и цвет; `shape`, `size`, `padding` и `elevation` отвечают за геометрию и глубину — это независимые оси, поэтому валидна любая их комбинация:

```tsx
<Box material="glass" tone="neutral" shape="rounded" elevation="overlay" padding={16}>
  <Text>Плавающая панель</Text>
</Box>
```

**`shape`** — алгоритм скругления углов. Само значение скругления по-прежнему берётся из окружающего `--radius-outer`, которое задаёт родительская область — `shape` определяет, как это значение используется, а не чему оно равно:

| Shape | Поведение угла |
| --- | --- |
| `rect` | Всегда жёсткий `0` — игнорирует любую окружающую область радиуса |
| `rounded` (по умолчанию) | Минимум `--radius-mini` (2px) — никогда не становится жёстким квадратом, кроме как при `rect` |
| `squircle` | Настоящий суперэллипс там, где браузер поддерживает `corner-shape`; уменьшенный `border-radius` как запасной вариант в остальных случаях |
| `circle` | Принудительно `50%` с `aspect-ratio: 1` — ширина следует за `size`/высотой, padding сбрасывается в `0` |
| `pill` | Всегда полная капсула, независимо от окружающего радиуса или размера |

**`size`** — именованный уровень, задающий одновременно минимальную высоту блока и его внутренние отступы (произвольное число/строка вместо этого делает блок квадратом такого размера — см. описание пропа `size` выше):

| Size | Высота |
| --- | --- |
| `mini` | 16px |
| `s` | 24px |
| `m` (по умолчанию) | 32px |
| `l` | 40px |
| `xl` | 48px |

**`elevation`** — объединённая роль z-index + тень, так что порядок наложения поверхности и визуальный сигнал глубины всегда меняются вместе:

| Elevation | Тень | Типичное применение |
| --- | --- | --- |
| `flat` (по умолчанию) | Нет | `Box` в покое, не приподнятый над страницей |
| `raised` | Лёгкая | Элемент `Tabs`, день в `DatePicker` |
| `sticky` | Мягкий нижний край | `Screen.Header`, заголовок колонки `DataTable` |
| `overlay` | Средняя | `Popover`, `Dropdown`, `Drawer` |
| `modal` | Тяжёлая | `Modal`, `Dialog` |
| `toast` | Самая тяжёлая | Тост-уведомление |

## Построение собственных компонентов

1. **Обращайтесь к `Box`, прежде чем писать стилизованный контейнер вручную.** Карточка, чип, таблетка-бейдж, плейсхолдер-плитка — если нужна заливка, граница или состояние hover/press, `Box`, скорее всего, уже это покрывает.
2. **Выбирайте материал по роли, а не по тому, как он выглядит в одной конкретной теме.** `plate` и `glass` могут выглядеть похоже в светлой теме и совсем по-разному в тёмной (тяжёлое на тени оформление `plate` против чистого блюра `glass`) — выбирайте, исходя из того, чем поверхность *является* (приподнятый контрол vs матовый оверлей), а не из снимка её текущего вида.
3. **`tone` — для статуса, `color` — для идентичности.** Не используйте `color` с сырым hex-значением, чтобы выразить «это опасно» — именно для этого нужен `tone="danger"`, и он остаётся корректным при смене темы и акцента бесплатно (см. [Тёмную тему](darkTheme)).
4. **Сопоставляйте проп взаимодействия с тем, что реально интерактивно.** `pressable` — на реально кликабельной поверхности, `editable` — только когда `asChild` оборачивает нативное текстовое поле, `focusable` — всегда, когда на элемент может попасть фокус с клавиатуры. Несовпадение либо скрывает реальную интерактивность, либо имитирует ту, которой нет.
