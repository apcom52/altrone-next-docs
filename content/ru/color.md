# Цвет

Любой цвет в Altrone берётся из токена, а не вписывается вручную hex-кодом. Это не просто стилистическое предпочтение — именно это позволяет тёмной теме, широкому цветовому охвату (wide-gamut) и контрасту уровня WCAG AA работать автоматически для компонента, автору которого вообще не пришлось об этом думать. Эта статья проходит по самой палитре, семантическим слоям поверх неё и объясняет, как использовать те же слои, когда вы строите собственные компоненты над Altrone.

## Базовая палитра

Каждый оттенок в Altrone — это 12-ступенчатая шкала плюс парный alpha-вариант (`--red-a9` рядом с `--red-9`), заданные в `display-p3` для широкого цветового охвата, с отдельными значениями для светлой и тёмной темы — не одна шкала, алгоритмически затемнённая. Десять оттенков доступны как переключаемый **accent**, плюс gray и black, которые не переключаются:

::playground{src=ColorAccentHuesDemo caption="Все десять доступных для accent оттенков, по 12 ступеней"}

Компоненты никогда не обращаются к сырому оттенку напрямую (ни в одном SCSS компонента нет `var(--red-9)`). Вместо этого они читают `--accent-N`, а `<Application accent="...">` перенаправляет, к какому оттенку это резолвится:

```tsx
<Application accent="indigo">{/* --accent-9 теперь везде резолвится в --indigo-9 */}</Application>
```

Gray и black дополняют базовую палитру — gray для всех нейтральных ролей фона/границы/текста, black строго как alpha-шкала (`--black-a1`…`--black-a12`, сплошного `--black-9` не существует) для скримов и теней, которым нужно затемнять то, что под ними, а не закрашивать фиксированным цветом:

::playground{src=ColorNeutralScaleDemo caption="Сплошная шкала gray и alpha-шкала black поверх тонированного фона"}

## Статусные цвета

`danger`, `success` и `warning` — это **фиксированные оттенки** (red, green, amber), независимые от того, какой `accent` выбран сейчас. Это сделано намеренно: если потребитель выберет `accent="red"` для своего бренда, состояния опасности всё равно должны читаться как «опасность», а не растворяться в остальном интерфейсе, который теперь делит с ними оттенок.

`info` — единственное исключение: он намеренно следует за `--accent`, а не за фиксированным оттенком, потому что его задача — привлечь внимание внутри основного потока, а не сигнализировать об универсальном состоянии, которое (в отличие от остальных трёх) должно оставаться узнаваемым независимо от брендинга:

::playground{src=ColorStatusRolesDemo caption="danger / success / warning / info, каждый как сплошной образец плюс пять ролевых токенов"}

## Шкала ролей

Каждый статус (и шкала gray, по образцу которой он построен) отображает свои 12 ступеней на пять ролей, названных по назначению. Зная это соответствие один раз, вы сможете прочитать CSS любого статуса, не запоминая, что означает каждая сырая ступень:

| Роль | Ступени | Используется для |
| --- | --- | --- |
| `background` | 1–2 | Фон страницы/панели для области статуса |
| `interactive` | 3–5 | Фон компонента (rest / hover / active) |
| `border` | 6–8 | Едва заметная граница → граница UI → граница при hover |
| `solid` | 9–10 | Сплошная заливка (например, заполненная кнопка danger) |
| `text` | 11–12 | Текст низкой / высокой контрастности |

На практике так и выглядит CSS компонента — он называет роль, а не сырую ступень:

```scss
.errorMessage {
  color: var(--danger-text-1);
  background: var(--danger-background-1);
  border: 1px solid var(--danger-border-1);
}
```

:::tip
Те же пять ролей стоят и за нейтральной шкалой gray (`--background-1`, `--border-1`, `--text-1`, …) — выучив шкалу ролей один раз, вы научитесь читать любой файл с цветами в кодовой базе, а не только статусные.
:::

## Состояние disabled

Отключённые элементы используют выделенные сплошные токены — `--disabled-background`, `--disabled-border`, `--disabled-text-color` — вместо `opacity`. Opacity непредсказуема поверх полупрозрачного/glass-материала: альфа-каналы складываются, поэтому один и тот же `opacity: 0.5` выглядит по-разному в зависимости от того, что находится под ним. Выделенный цвет одинаков независимо от подложки.

```scss
/* Неправильно — выглядит по-разному над сплошной карточкой и над glass-поверхностью */
.disabled {
  opacity: 0.5;
}

/* Правильно — один предсказуемый результат везде */
.disabled {
  background: var(--disabled-background);
  border-color: var(--disabled-border);
  color: var(--disabled-text-color);
}
```

## Категориальные цвета

Отдельный набор из 10 цветов для различения одинаковых по форме элементов по **идентичности** — аватар на человека, тег на метку — а не для передачи смысла, как это делают статусные цвета. Каждый элемент — это сплошная ступень своего оттенка, а не оттенок одного и того же цвета, поэтому соседние значения остаются визуально различимыми:

::playground{src=ColorCategoricalDemo caption="Десять категориальных цветов, от --category-1 до --category-10"}

Ни один из них не выбирается явно — одна и та же строка-идентичность всегда резолвится в один и тот же элемент через `ColorUtils.getCategoricalColorIndex(seed)`, детерминированный хэш из строки в индекс. `Avatar` уже использует это: не передавайте явный `backgroundColor`, и компонент откатится на категориальный цвет, ключом для которого служит полное имя человека — поэтому «Ada Lovelace» всегда одного и того же цвета везде, где она появляется, без того, чтобы какой-либо компонент отслеживал назначение.

```tsx
import { ColorUtils } from "altrone-ui";

const index = ColorUtils.getCategoricalColorIndex("Ada Lovelace");
// один и тот же вход — один и тот же индекс, каждый раз, без общей таблицы назначений
```

## Точечные токены

Несколько одноразовых цветов, которые не принадлежат ни одной из шкал выше:

- **`--color-overlay-scrim`** — затемняющий слой за `Modal`/`Drawer`. Общий для обоих вместо того, чтобы каждый определял свою копию того же значения.
- **`--color-header-backdrop`** — размытая полоса за `Screen.Header`. Намеренно тонирован в акцент, а не в нейтральный серый — осознанное решение, а не недосмотр.
- **`--color-selection`** — фон `::selection` для выделенного текста, подключён глобально.

## Использование цвета в собственных компонентах

Если вы строите компонент поверх Altrone — карточку, статусный индикатор, специфичный для вашего домена виджет — к вашему CSS применяются те же правила, что и к CSS самой библиотеки:

1. **Никогда не вписывайте hex-значение вручную.** Сначала ищите ролевой токен (`--danger-text-1`, `--background-2`, `--accent-9`). Если ничего существующего не подходит — это повод поднять вопрос, а не изобретать одноразовый цвет.
2. **Выбирайте роль по назначению, а не по тому, как она выглядит сегодня.** `--danger-text-1` и `--text-1` могут рендериться похоже в какой-то теме, но означают разные вещи — будущая правка палитры или тёмной темы снова может их развести.
3. **Никогда не передавайте состояние только цветом.** Сопровождайте статусный цвет текстом или иконкой — это жёсткое требование, а не стилистическое пожелание; см. статью [Доступность](accessibility), почему.
4. **Проверяйте контраст, а не предполагайте его.** Встроенные ролевые токены уже выверены под WCAG AA, но собственное сочетание (например, текст `--warning-solid-1` на светлом фоне) может не пройти проверку — убедитесь в этом до релиза.

:::warning
Сырое hex-значение в CSS вашего компонента — один из самых быстрых способов сломать тёмную тему именно для него: оно не перекрасится при смене темы, акцента или будущей ревизии палитры, тогда как всё вокруг, построенное на токенах, перекрасится.
:::
