# Application

`Application` — корневой компонент каждого приложения на Altrone UI. Он устанавливает тему, акцентный цвет, язык интерфейса, систему диалогов и уведомлений. Все остальные компоненты должны находиться внутри него — без этой обёртки они не получат нужных CSS-переменных и контекстов.

## Минимальная настройка

```tsx
import { Application } from 'altrone-ui';
import 'altrone-ui/dist/style.css';

export default function App() {
  return (
    <Application>
      {/* ваше приложение */}
    </Application>
  );
}
```

Без пропов компонент работает с разумными значениями по умолчанию: тема `auto`, акцент `blue`, язык `en`.

## Тема

Проп `theme` управляет цветовой схемой. Значение `auto` отслеживает системный параметр `prefers-color-scheme` и переключается в реальном времени — если пользователь меняет тему в ОС, интерфейс адаптируется без перезагрузки страницы.

```tsx
{/* Следит за системной темой — поведение по умолчанию */}
<Application theme="auto">

{/* Всегда светлая */}
<Application theme="light">

{/* Всегда тёмная */}
<Application theme="dark">
```

:::note
При смене темы Altrone выставляет атрибут `data-altrone-theme` одновременно на `<html>` и на корневой элемент. Это нужно, чтобы порталы (диалоги, тултипы, дропдауны), которые рендерятся вне основного дерева, тоже получили правильные CSS-переменные.
:::

:::note
`Application` также зеркалит фон приложения на `<body>` и `<html>` (инлайн-стилем, с восстановлением при размонтировании) и обновляет его при смене темы. Без этого зона overscroll (rubber-band при скролле, особенно в Safari) мигала бы белым — цветовые токены объявлены на корневом элементе, а не на `<html>`.
:::

### Сохранение выбранной темы

Проп `persistTheme` запоминает выбранную пользователем тему в `localStorage` и восстанавливает её при следующем визите — приоритетнее `theme`/системной темы, если значение уже сохранено.

```tsx
<Application persistTheme>
  <App />
</Application>
```

:::note
Сохранение включается только после того, как пользователь хотя бы раз явно переключил тему (через `useAltroneTheme()`) — до этого момента решение принимает проп `theme`/системные настройки. Подробнее о переключении темы и хуке `useAltroneTheme()` — в статье [Тёмная тема](darkTheme).
:::

## Акцентный цвет

`accent` задаёт первичный цвет, который используется во всех компонентах: кнопки `submit`, отмеченное состояние `Switch`/`Checkbox`/`Radio`, слайдеры, индикаторы прогресса и загрузки. Выбирайте его один раз — смешивать акценты в рамках одного приложения не стоит.

```tsx
<Application accent="indigo">
```

Доступные значения: `red`, `pink`, `purple`, `indigo`, `blue`, `teal`, `amber`, `brown`.

## Локализация

### Язык интерфейса

Проп `language` задаёт язык встроенных строк: пустые состояния, сообщения об ошибках валидации, подписи в пагинации и других компонентах. Он не влияет на ваш контент — только на тексты внутри самой библиотеки.

```tsx
<Application language="ru">
```

Доступные языки: `en` (английский), `ru` (русский), `fr` (французский), `de` (немецкий), `es` (испанский), `zh` (китайский), `pt` (португальский), `tr` (турецкий).

### Переопределение отдельных строк

Если нужно заменить конкретную фразу без создания полного перевода, используйте `customLabels`. Ключи соответствуют формату `<компонент>.<строка>`.

```tsx
<Application
  language="en"
  customLabels={{
    'autocompleteInput.loadError': 'Failed to load suggestions',
    'dataTable.empty': 'Nothing here yet',
  }}
>
```

## Тосты и уведомления

`Application` монтирует систему тостов и уведомлений (`showToast`/`showNotification`/`dismissNotification`) — вызывать их можно из любого места, включая код за пределами React. Расположение стека — общее для всего приложения, а не для отдельного вызова: задаётся один раз через `toastPlacement` (вертикальный край, по горизонтали тосты всегда центрированы) и `notificationPlacement` (угол экрана).

```tsx
<Application toastPlacement="top" notificationPlacement="top-start">
  <App />
</Application>
```

:::note
`notificationPlacement` использует ту же схему `сторона-выравнивание`, что и `placement` у `Popover`/`Tooltip`: сторона (`top`/`bottom`) — физическая, а выравнивание (`start`/`end`) — логическое и резолвится относительно направления письма (`start` = слева, `end` = справа в LTR).
:::

## Полная конфигурация

```tsx
<Application theme="auto" accent="blue" language="ru">
  <App />
</Application>
```

## Рендер в собственный корневой элемент (asChild)

По умолчанию `Application` рендерит собственный `<div>`. Проп `asChild` переносит его атрибуты и классы на единственный переданный дочерний элемент вместо этого — например, чтобы использовать в качестве корня ваш собственный `<body>`.

```tsx
<Application asChild theme="auto" language="ru">
  <body>
    <App />
  </body>
</Application>
```

## Использование в Next.js

В Next.js App Router `Application` должен находиться в клиентском компоненте. Обычно это корневой layout.

```tsx
// app/layout.tsx
import { Application } from 'altrone-ui';
import 'altrone-ui/dist/style.css';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="ru">
      <Application asChild theme="auto" language="ru">
        <body>{children}</body>
      </Application>
    </html>
  );
}
```

:::warning
Если вы используете серверные компоненты, не импортируйте `Application` напрямую в серверный модуль — оберните его в отдельный клиентский компонент с директивой `'use client'`.
:::

## Свойства

:::prop[theme]{type="'auto' | 'light' | 'dark'" default="'auto'"}
Цветовая тема. `auto` следит за системным `prefers-color-scheme` и обновляется в реальном времени.
:::

:::prop[persistTheme]{type="boolean" default="false"}
Запоминает выбранную тему (`light`/`dark`) в `localStorage` и восстанавливает её при следующем визите — после того как пользователь хотя бы раз явно переключил тему.
:::

:::prop[accent]{type="'red' | 'pink' | 'purple' | 'indigo' | 'blue' | 'teal' | 'amber' | 'brown'" default="'blue'"}
Акцентный цвет дизайн-системы. Применяется глобально ко всем компонентам через CSS-переменные.
:::

:::prop[language]{type="'en' | 'ru' | 'fr' | 'de' | 'es' | 'zh' | 'pt' | 'tr'" default="'en'"}
Язык встроенных строк компонентов. Не влияет на пользовательский контент.
:::

:::prop[customLabels]{type="Partial<Localization>" default="{}"}
Переопределение отдельных строк локализации. Дополняет, а не заменяет выбранный `language`.
:::

:::prop[toastPlacement]{type="'top' | 'bottom'" default="'bottom'"}
Вертикальный край стека тостов (по горизонтали всегда центрирован).
:::

:::prop[notificationPlacement]{type="'top-start' | 'top-end' | 'bottom-start' | 'bottom-end'" default="'bottom-end'"}
Угол стека уведомлений — та же схема `сторона-выравнивание`, что у `placement` в `Popover`/`Tooltip`.
:::

:::prop[asChild]{type="boolean" default="false"}
Переносит атрибуты и классы корня на единственный дочерний элемент вместо рендера собственного `<div>` — например, для использования вашего `<body>` в качестве корня.
:::

:::prop[children]{type="ReactNode"}
Приложение, оборачиваемое `Application`. При `asChild` должен быть единственным React-элементом — его собственные дети становятся содержимым дерева провайдеров.
:::

:::prop[ref]{type="Ref<HTMLDivElement>"}
Ref на корневой элемент — обычный `<div>`, либо, при `asChild`, тот дочерний элемент, на который перенесены атрибуты.
:::

## Рекомендации

**Один экземпляр на всё приложение.** `Application` не предназначен для вложения или использования несколько раз. Один корневой экземпляр устанавливает единую среду для всего дерева компонентов.

**`theme="auto"` — правильный дефолт.** Пользователи, выбравшие тёмную тему в системе, ожидают её везде. Не лишайте их этого без причины.

**Не меняйте акцент динамически без необходимости.** Если задача — дать пользователю выбор темы, это нормально. Но если акцент меняется в зависимости от контекста страницы — это сигнал, что интерфейс утратил единство.
