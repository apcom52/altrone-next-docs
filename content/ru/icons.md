# Иконки

Altrone не поставляет набор иконок, из которого можно выбирать. Нет компонента `<Icon name="trash" />`, нет собственного словаря иконок, нет реестра для просмотра. Любой проп, принимающий иконку — `icon` у `Button`, `icon` у `TextInput`, `icon` у `Toolbar.Action` и так далее — типизирован просто как `ReactElement`. Вы приносите ту библиотеку иконок, которую уже использует ваше приложение (или обычные инлайновые SVG), и всё работает.

```ts
// Button.types.ts — весь контракт целиком
icon?: ReactElement;
```

Это осознанное решение, а не недосмотр: библиотека компонентов, которая поставляет собственный набор иконок, заставляет каждого потребителя либо принять его целиком, либо поддерживать сразу два словаря иконок параллельно. Принимая обычный элемент вместо этого, единственный выбор иконок, о котором вам вообще приходится думать — тот, что уже сделан в вашем приложении.

```tsx
import { Button } from "altrone-ui";
import { Trash2 } from "lucide-react";
// или точно так же валидно:
// import { TrashIcon } from "@heroicons/react/24/outline";
// import { Trash } from "phosphor-react";

<Button label="Удалить" icon={<Trash2 />} />;
```

## Что использует сама Altrone

Собственный интерфейс Altrone — стрелки в `Select`/`Dropdown`, иконка подсказки в `Form.Field` и подобные встроенные детали, которые библиотека рисует сама, а не запрашивает у вас — построены на [lucide-react](https://lucide.dev/). Это деталь реализации собственных компонентов библиотеки, а не публичный API, к которому вы привязаны: ничто не требует, чтобы ваше приложение тоже использовало lucide-react.

:::note
Если вы всё же уже используете lucide-react, вы получаете одно конкретное преимущество бесплатно — см. раздел про размер ниже.
:::

## Размер

Компоненты, принимающие иконку, задают размер её слота через `font-size` плюс собственную CSS-переменную, отдельную для каждого размера компонента:

```scss
/* Упрощённо — как Button задаёт размер своей иконки */
.Button {
  --button-icon-size: 16px; /* size="m", значение по умолчанию */
}
.ButtonIcon {
  font-size: var(--button-icon-size);
}
```

Это работает благодаря тому, что сама иконка резолвит свою ширину/высоту в `1em` — именно так и поступают иконки lucide-react, благодаря глобальному правилу, которое Altrone поставляет и которое нацелено на класс `lucide`, присутствующий у каждой иконки lucide:

```scss
:global(.lucide) {
  width: 1em !important;
  height: 1em !important;
  color: currentColor;
}
```

Это и есть конкретная выгода от использования lucide-react вместе с Altrone: передайте иконку — и она автоматически подстроится под нужный размер и цвет окружающего компонента, без явных пропов `size`/`color` на самой иконке.

:::warning
Это автоматическое масштабирование привязано именно к классу `lucide`. Если вы принесёте другую библиотеку иконок, её иконки не подхватят `--button-icon-size` сами по себе — большинство библиотек иконок принимают собственный явный проп размера (`<TrashIcon className="size-4" />`, `<Trash size={16} />`, …), так что задавайте размер вручную, или оборачивайте иконки в свой CSS, повторяющий соглашение `1em`.
:::

## Контролам только с иконкой всё равно нужно имя

Передача одной иконки без видимой подписи не даёт контролу доступное имя бесплатно — это верно независимо от того, какая библиотека нарисовала SVG. Проп `label` у `Button` остаётся обязательным даже при `showLabel={false}`, скрывающем его визуально — специально для того, чтобы это нельзя было пропустить случайно:

```tsx
<Button label="Удалить элемент" showLabel={false} icon={<Trash2 />} />
```

Полное правило и что делать, если вы собираете контрол только с иконкой с нуля, а не через `Button`, см. в статье [Доступность](accessibility).

## Построение собственных компонентов

Если вы добавляете слот под иконку в собственный компонент поверх Altrone:

1. **Принимайте `ReactElement` (или `ReactNode`), а не строку-имя.** Проп на основе имени (`icon="trash"`) подразумевает реестр за ним — именно ту связанность, которой эта архитектура избегает.
2. **Задавайте размер через `font-size` + `1em`, по тому же соглашению, что и библиотека** — тогда любой набор иконок, включая собственный набор потребителя, резолвится в нужный размер, если сам он размерен в `1em`.
3. **Не добавляйте lucide-react (или любую другую библиотеку иконок) в жёсткие зависимости переиспользуемого компонента**, если только это не внутренний интерфейс вроде иконки подсказки в `Form.Field`. Переиспользуемый компонент, принимающий иконку, должен работать с тем, что уже импортировано у потребителя.
