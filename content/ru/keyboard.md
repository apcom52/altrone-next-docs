# Клавиатура

Каждый интерактивный элемент в Altrone работает от одной только клавиатуры, но «поддержка клавиатуры» — это не одно поведение, а несколько разных паттернов, в зависимости от того, чем на самом деле является контрол: составной виджет, значение, которое перетаскивают, оверлей, или контрол, который лишь намекает на сочетание клавиш, но сам его не реализует. Эта статья — про то, как их различать.

## Составные виджеты: roving tabindex

Набор связанных контролов, ведущих себя как единое целое, занимает ровно одну остановку в Tab-последовательности страницы; стрелки перемещают фокус между его элементами. `Tabs` — реальный, поставляемый пример этого паттерна: собственный список табов сам обрабатывает фокус:

```ts
// Tabs.tsx — реальные клавиши, которые он обрабатывает
'ArrowRight', 'ArrowLeft', 'ArrowDown' /* + 'Home', 'End' */
```

Только активный таб входит в Tab-последовательность страницы; стрелки (и `Home`/`End`) перемещают фокус по остальным, никогда не попадая туда через Tab. Стройте собственный составной виджет так же — полную механику roving `tabindex` см. в [Доступности](accessibility).

## Значения, которые можно подталкивать: стрелки как прямое манипулирование

Два реальных контрола позволяют стрелкам менять значение напрямую, а не просто перемещать фокус:

- **`Slider`** меняет значение по шагу через `ArrowLeft`/`ArrowDown` (уменьшение) и `ArrowRight`/`ArrowUp` (увеличение).
- **Разделитель `Splitter`** таким же образом изменяет размер соседних панелей — стрелки подталкивают разделение на шаг, как только разделитель получает фокус.

Оба относятся к клавиатуре как к альтернативе перетаскиванию, а не как к запасному варианту, прикрученному отдельно — тот же путь `onChange` (или ресайза), что запускает перетаскивание курсором.

## Оверлеи: `Escape` и куда уходит фокус

`Modal`, `Drawer`, `Popover` и `Dropdown` все закрываются по `Escape` и возвращают фокус туда, откуда были открыты — полная механика (и почему возврат фокуса важен) разобрана в [Доступности](accessibility). Здесь не нужно ничего дополнительного, кроме как строить собственный оверлей так же.

## Подсказка сочетания клавиш — это не само сочетание

Проп `kbd` у `Button` рендерит небольшой бейдж (например, `⌘S`) во всплывающей подсказке, которая появляется при `showLabel={false}` — но это подпись, а не привязка. Задание `kbd="⌘S"` не делает так, чтобы `⌘S` что-то выполняло — вам всё равно нужно самостоятельно зарегистрировать реальный обработчик `keydown` там, где это сочетание должно жить:

```tsx
<Button label="Сохранить" showLabel={false} icon={<Save />} kbd="⌘S" />
```

```tsx
useEffect(() => {
  const handler = (e: KeyboardEvent) => {
    if (e.metaKey && e.key === "s") {
      e.preventDefault();
      save();
    }
  };
  window.addEventListener("keydown", handler);
  return () => window.removeEventListener("keydown", handler);
}, []);
```

## Построение собственных компонентов

1. **Составной виджет получает roving `tabindex`**, а не `tabindex="0"` на каждом элементе — одна остановка в Tab-последовательности страницы, стрелки внутри него, так же как уже работает `Tabs`.
2. **Перетаскиваемое значение должно принимать и стрелки**, изменяя то же самое значение, что менялось бы перетаскиванием курсором — и `Slider`, и `Splitter` относятся к этому как к одному пути кода, а не к двум.
3. **Оверлей закрывается по `Escape` и возвращает фокус на свой триггер** — точную механику см. в [Доступности](accessibility).
4. **Подсказка `kbd` не подключает себя сама.** Показ `⌘S` рядом с кнопкой — это обещание пользователю: подкрепите его реальным обработчиком `keydown`, или не показывайте вовсе.
