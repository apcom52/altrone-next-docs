# Анимация

Анимация в Altrone по умолчанию учитывает `prefers-reduced-motion`, без того, чтобы каждый компонент проверял это сам. Это разделено на три уровня — в зависимости от того, как именно реализовано движение: обычный CSS-переход, JS-анимация или вручную рассчитанный `setTimeout` — плюс один нюанс, который важнее самой механики: сниженная анимация не значит «анимации нет вовсе».

## Уровень 1: обычные CSS-переходы

Длительности и кривые смягчения — это CSS-переменные, заданные один раз и обнуляемые под `prefers-reduced-motion: reduce` в корне:

```scss
:global([data-altrone-root='true']) {
  --motion-duration-fast: 0.1s;
  --motion-duration-base: 0.2s;
  --motion-easing-standard: ease;
}

@media (prefers-reduced-motion: reduce) {
  :global([data-altrone-root='true']) {
    --motion-duration-fast: 0s;
    --motion-duration-base: 0s;
  }
}
```

Любой компонент, чей CSS обращается к `var(--motion-duration-base)` вместо того, чтобы вписывать `0.2s` напрямую, автоматически получает сниженную анимацию — без собственного медиа-запроса. Правда, это покрывает только обычные `transition` — зацикленная `@keyframes`-анимация с собственной фиксированной длительностью не остановится только оттого, что эти переменные стали `0s` (длительность `0s` у *бесконечной* анимации всё равно зацикливается, просто мгновенно — это не то же самое, что остановка). Такой случай требует собственного явного правила — см. ниже.

## Уровень 2: JS-анимация

Компоненты, анимированные через библиотеку `motion` (`Modal`, `Popover`, `Tooltip`, `Notifications`, `Spoiler` и другие), вообще не покрываются уровнем CSS. `Application` один раз оборачивает всё дерево в `<MotionConfig reducedMotion="user">`:

```tsx
<MotionConfig reducedMotion="user">{children}</MotionConfig>
```

Поскольку `MotionConfig` распространяется через React-контекст, это покрывает любой `motion.div` (и подобные) где угодно внутри `<Application>` — включая те, что в ваших собственных компонентах — без того, чтобы каждый из них сам читал `prefers-reduced-motion`.

## Уровень 3: ручной тайминг в JS

Для чего-то вроде `setTimeout` перед размонтированием элемента после его анимации исчезновения используйте тот же SSR-safe хук, которым остальная кодовая база проверяет сниженную анимацию, вместо того чтобы вписывать длительность напрямую:

```tsx
import { useMediaMatch } from "altrone-ui";

function useAutoDismissDelay() {
  const reducedMotion = useMediaMatch("(prefers-reduced-motion: reduce)");
  return reducedMotion ? 0 : 300;
}
```

Ни одному компоненту в библиотеке этот уровень пока не требуется — тайминг размонтирования сегодня идёт через собственный `AnimatePresence` библиотеки `motion`, который уже покрывается уровнем 2. Обращайтесь к этому паттерну только тогда, когда у вас есть по-настоящему ручной таймаут, не управляемый `motion`.

## Сниженная анимация ≠ анимации нет

Это стоит понять прежде, чем писать любое переопределение: [WCAG 2.3.3](https://www.w3.org/WAI/WCAG21/Understanding/animation-from-interactions) не требует убрать всё движение целиком — только **декоративное, автоматически проигрывающееся или зацикленное** движение, которое не несёт информации. Движение, которое является прямой обратной связью на только что совершённое пользователем действие — `Splitter.Divider`, следующий за курсором при перетаскивании, `Spoiler`, разворачивающийся по клику — не об этом, и его удаление может сделать интерфейс менее отзывчивым, а не более доступным.

Два реальных примера из библиотеки, которые осознанно решены по-разному:

- **Мерцание `Skeleton`** чисто декоративно — зацикленная анимация цвета фона, которая не сообщает ничего такого, чего не сообщал бы статичный блок-заглушка. При сниженной анимации оно полностью отключается:

  ```scss
  .Skeleton {
    animation: skeleton-animate 3s ease-in-out infinite;

    @media (prefers-reduced-motion: reduce) {
      animation: none;
    }
  }
  ```

- **Спиннер `Loading`** — функциональный индикатор состояния: единственный сигнал, что фоновая операция всё ещё выполняется. Он намеренно продолжает вращаться при сниженной анимации, с комментарием, чтобы будущий читатель не принял это за недосмотр:

  ```scss
  /** Deliberately not reduced under prefers-reduced-motion: a functional
      loading state, not decorative motion. */
  .Spinner {
    animation: rotate 2s linear infinite;
  }
  ```

## Построение собственных компонентов

1. **Не предполагайте, что «остановить» — всегда правильный ответ для сниженной анимации.** Сначала спросите себя, что именно это движение сообщает. Пара `Skeleton`/`Loading` выше пришла к противоположным выводам по конкретной причине — одно декоративно, другое является единственной обратной связью о том, что что-то происходит, — а не потому, что одно «важнее» другого.
2. **Обращайтесь к `--motion-duration-fast`/`--motion-duration-base` в обычных CSS-переходах** вместо того, чтобы вписывать длительность напрямую — тогда уровень 1 покрывает вас автоматически.
3. **Зацикленной `@keyframes`-анимации нужно собственное явное правило для сниженной анимации.** Общие токены длительности не остановят бесконечный цикл с собственным фиксированным таймингом — напишите `@media (prefers-reduced-motion: reduce) { animation: none }` сами, как только решите (согласно пункту 1), что именно этот цикл действительно должен останавливаться.
4. **Работа с библиотекой `motion` не требует дополнительных усилий.** Всё, что рендерится внутри `<Application>`, уже наследует `<MotionConfig reducedMotion="user">` — вам не нужно самостоятельно читать медиа-запрос только потому, что вы используете `motion.div`.
5. **Ручной таймаут** — `setTimeout`, привязанный к длительности анимации, должен использовать `useMediaMatch` (см. уровень 3 выше), а не зашитое число.
