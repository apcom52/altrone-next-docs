# Scrollable

Браузерные полосы прокрутки занимают место и выглядят по-разному в каждой операционной системе. `Scrollable` решает обе проблемы: оверлейные полосы появляются поверх содержимого, не меняя ширину контейнера, и автоматически скрываются, когда пользователь не взаимодействует с областью. Интерфейс остаётся чистым — прокрутка проявляется только тогда, когда она нужна.

## Базовое использование

Оберните содержимое в `Scrollable`. Компонент занимает 100% высоты родителя — задайте фиксированную высоту снаружи.

```tsx
<div style={{ height: 300 }}>
  <Scrollable>
    {items.map((item) => <Item key={item.id} {...item} />)}
  </Scrollable>
</div>
```

## Программная прокрутка

`ref` указывает на внутренний viewport-элемент — тот же `HTMLDivElement`, который вы скроллите программно. Используйте `scrollTo`, `scrollTop` и любые другие стандартные методы.

```tsx
const viewportRef = useRef<HTMLDivElement>(null);

const scrollToTop = () => {
  viewportRef.current?.scrollTo({ top: 0, behavior: "smooth" });
};

<Scrollable ref={viewportRef}>
  <LongContent />
</Scrollable>
```

## Макет с несколькими прокручиваемыми областями

Используйте `Scrollable` для независимой прокрутки в разных зонах интерфейса — например, в сайдбаре и основном контенте одновременно.

```tsx
<div style={{ display: "flex", height: 600 }}>
  <aside style={{ width: 200, flexShrink: 0 }}>
    <Scrollable>
      <Navigation />
    </Scrollable>
  </aside>
  <main style={{ flex: 1 }}>
    <Scrollable>
      <PageContent />
    </Scrollable>
  </main>
</div>
```

## Свойства

:::prop[children]{type="ReactNode"}
Прокручиваемое содержимое.
:::

:::prop[ref]{type="Ref<HTMLDivElement>"}
Указывает на viewport-элемент (внутренний прокручиваемый `div`). Используйте для программной прокрутки.
:::

:::note
Все стандартные атрибуты `HTMLDivElement` принимаются и применяются к внешней обёртке — не к viewport. Для управления viewport используйте `ref`.
:::

## Рекомендации

**Задавайте высоту снаружи.** `Scrollable` не знает, сколько места ему выделено — он заполняет родителя целиком. Если родитель не имеет явной высоты, прокрутка не появится: элемент просто вырастет вместе с содержимым.

**Используйте `Scrollable` для областей, а не для страниц.** Прокрутка всего документа браузером — это ожидаемое поведение, хорошо работающее с кнопкой «назад», позицией скролла и поиском на странице. `Scrollable` — для ограниченных зон: сайдбаров, чатов, списков внутри фиксированных панелей.

**Не вкладывайте прокручиваемые области без причины.** Вложенная прокрутка дезориентирует: пользователь теряет понимание того, что именно прокручивает. Если содержимое само по себе длинное — возможно, ему нужна собственная страница.

**`Drawer` и `Modal` уже используют `Scrollable` внутри.** Не оборачивайте `content` этих компонентов в дополнительный `Scrollable` — это создаст вложенную прокрутку.
